HyperAVNet: Parameter-Efficient Hypercomplex Audio-Visual Fusion for Fish Feeding Intensity Assessment

Model architecture, training recipe, ablation protocol and paper-writing guide for the AV-FFIA dataset
Code bojesomo/hypercomplex-network, branch claude/av-ffia-hypercomplex-classification-x87kyc Package avffia/ on fast_hypercomplex Status implemented and unit-tested; not yet trained on AV-FFIA Reference Cui et al., Multimodal Fish Feeding Intensity Assessment in Aquaculture, arXiv:2309.05058v3 (U-FFIA)

Summary. HyperAVNet is an audio-visual classifier for the four-class AV-FFIA task (none, weak, medium, strong feeding). Hypercomplex (PHM / Hamilton-product) layers are used wherever parameters live: point-wise convolutions, attention projections, MLPs, stage projectors and the classifier. Audio and video are fused by a new Hypercomplex Component Fusion (HCF) block. It treats the shared bottleneck state, the audio view, the video view and their interaction as the components of one quaternion (or octonion) and mixes them with a single Hamilton product. HCF can be attached at any depth of the two backbones. A configurable deep-to-early schedule, with zero-initialised cross-modal feedback, sweeps from late fusion to progressive early fusion. Large pretrained audio and video models (PANNs CNN10/14, S3D and other timm and torchvision networks) serve either as a teacher for multi-level distillation or as frozen feature extractors under a hypercomplex side network. The default quaternion student has 2.14 M parameters (3.7× fewer than the identical real-valued network, 7.88 M) and costs 1.18 GMACs per 2 s clip (2.36 GFLOPs). That is 10× fewer parameters and 13× less compute than U-FFIA (21.6 M, 15.5 GMACs) and 16× / 52× less than the current best AV model on AV-FFIA, cross-attention fusion at 0.917 accuracy (35.1 M, 60.9 GMACs). The accuracy target is therefore > 0.917, at an order of magnitude lower cost.

Read this first: what is and is not established Our own parameter, FLOP, shape and latency figures were measured from the implemented code. Published baselines are quoted from the U-FFIA paper (Tables I–V). No accuracy of HyperAVNet on AV-FFIA has been measured yet: there was no GPU or dataset in the build environment. Claims of beating the state of the art must therefore wait for the experiments in §8. Where a design choice is a hypothesis to be tested, this report says so.

1  Task, data, protocol and published SOTA

AV-FFIA (Cui et al., U-FFIA) has 27,000 synchronised two-second audio-video clips of Oplegnathus punctatus feeding in a recirculating tank (3 m diameter, 0.75 m deep), 6,750 per class. Audio was recorded underwater by a hydrophone at 256 kHz; video by an overhead camera at 25 fps (50 frames per clip). A feeding technician labelled each one-minute recording as None, Weak, Medium or Strong, and recordings were then cut into 2 s segments. The data pipeline reproduces the U-FFIA conventions exactly, so results are directly comparable:

What the published results imply for this design (1) Pretrained CNNs beat transformers on AV-FFIA (CNN10 0.859 vs AST 0.736; S3D 0.898 vs ViViT 0.743), so the recommended teacher is now PANNs CNN10 + S3D (§7). AST and VideoMAE are kept only as an ablation. (2) Cross-attention (0.917) beat self-attention (0.892) and especially MBT (0.724). U-FFIA attributes MBT's failure to bottlenecks that "attend to each modality sequentially". HCF instead reads each modality with its own cross-attention, in parallel, and then mixes them in one Hamilton product (§5). This addresses that critique directly. (3) Robustness to noise is part of the evaluation standard on this dataset, so it is now built into the pipeline. (4) The efficient-model bar is U-FFIA's 21.6 M / 15.5 GMACs; the student is designed an order of magnitude below it.

2  Architecture overview

Figure 1 shows the full model. Each backbone returns a list of stage tokens from shallow to deep. A small set of shared bottleneck tokens Z (8 × 192) carries the fused state through the fusion blocks. At every fusion stage s, hypercomplex projectors map the audio tokens as and video tokens vs into the fusion width D. An HCF block then updates Z, and a zero-initialised hypercomplex gate feeds the result back into both streams. The classifier reads the pooled bottleneck together with the pooled last-stage audio and video tokens. Two auxiliary unimodal heads supervise each branch on its own.

3  Hypercomplex layers: the parameter-sharing mechanism

A hypercomplex layer with n components splits its input and output features into n equal parts and stores only n weight blocks W0, …, Wn−1, each of size (dout/n) × (din/n). The full kernel is assembled from these blocks with the signed arrangement of the algebra's multiplication table (complex, quaternion, octonion or sedenion). In fast_hypercomplex this is fast_hypercomplex(weights, n, get_comp_mat(n)). Every output component is therefore a signed combination of every input component, through shared weights:

y = K(W0,…,Wn−1) x + b,    #params = dindout / n + dout    (vs. dindout + dout for a real layer)(1)
Point to make in the paper The weight sharing is a structural prior: each feature group is processed by every weight block, with fixed sign patterns. This keeps cross-group interactions while removing 1 − 1/n of the parameters, which acts as a regulariser on a dataset of AV-FFIA's size. Compute is not reduced, because the assembled kernel is dense (see §9). State this explicitly: reviewers will check.

4  Hypercomplex student backbones

Both student backbones are four-stage stacks of hypercomplex inverted-residual (Hyper-IR) blocks (Fig. 3), with the MobileNetV2/EfficientNet layout: 2D on log-mel for audio, 3D for video. The two point-wise convolutions hold almost all of a block's parameters, so they are the hypercomplex ones. The depth-wise convolution stays real. Both backbones are stage-wise: the AV model runs them one stage at a time, which is what makes the cross-modal feedback of §6 possible.

Tokenisation. Audio stage maps are pooled over frequency, as mean + max (the max keeps short splash and feeding transients), which gives one token per time frame. U-FFIA's audio encoder pools the same way (average over frequency, then max + mean over time). Video maps are adaptively pooled to a 2 × 2 spatial grid per time step, which keeps coarse location (where the feeding activity is) while keeping fusion cheap.

5  Hypercomplex Component Fusion (HCF)

HCF is the main methodological contribution. Its inputs are the bottleneck Z ∈ ℝNb×D and the projected stage tokens A = Pa,s(as) and V = Pv,s(vs). HCF first reads each modality with its own hypercomplex cross-attention. It then builds a hypercomplex number whose components are the modality-specific views and their interactions:

za = Z + XAttnH(LN Z, LN A),    zv = Z + XAttnH(LN Z, LN V)(2)
q = Z·e0 + za·e1 + zv·e2 + (ẑa ⊙ ẑv)·e3    (quaternion; ẑ = LN z)(3)
octonion adds  (za − zv)·e4 + (Ẑ⊙ẑa)·e5 + (Ẑ⊙ẑv)·e6 + (Ẑ⊙ẑa⊙ẑv)·e7;   complex uses (za, zv)(4)
Z ← Z + γ1 ⊙ HyperLinearm(q),    Z ← Z + γ2 ⊙ HyperMLP(LN Z),   m ∈ {2, 4, 8}(5)

5.1  Baselines provided for the fusion-operator ablation

  • MBT (attention bottleneck; Nagrani et al. 2021; 0.724 on AV-FFIA in U-FFIA Table III): [A; Z] and [V; Z] each go through a hypercomplex transformer block, and the two bottleneck updates are averaged. It has about the same parameters as HCF (2.138 M vs 2.137 M in total), so the comparison is iso-parameter.
  • Concat: the pooled [Z, mean A, mean V] through a gated hypercomplex linear layer (1.851 M total).
Hypotheses to test (H1–H3) H1 HCF > MBT at equal parameters, and HCF ≥ the published cross-attention result (0.917). Each modality is read in parallel rather than sequentially (U-FFIA's explanation of MBT's failure), and the multiplicative za⊙zv component explicitly models agreement between the feeding sounds (chewing, tail-slapping) and the visible aggregation and surface agitation that U-FFIA §V-C describes. H2 Octonion HCF ≥ quaternion HCF, at the same parameters, from the extra interaction terms. H3 HCF is more robust than concatenation under modality dropout and corruption (test with one modality blanked at evaluation time).

6  Fusion depth: the deep-to-early schedule and feedback

The setting fusion_stages picks the stages where an HCF block is attached. The prescribed ablation moves from deep to early. Fusion first happens only at the last stage (late fusion), then progressively earlier stages are added, until fusion runs from the first stage on. Single-stage variants show at which depth fusion is most useful. With stage-wise backbones, each fusion stage s < S−1 also sends a feedback gate into both streams before stage s+1:

ha ← ha ⊙ (1 + tanh(Ga,s mean Z)),    hv ← hv ⊙ (1 + tanh(Gv,s mean Z)),    G = HyperLinear, zero-init(6)

Because G starts at zero, training starts exactly at the feedback-free (side-fusion) model. A unit test checks this equivalence. The network then learns how much audio context should modulate the video features and vice versa. This is true early fusion rather than fusion of independently computed features.

Hypotheses to test (H4–H5) H4 Accuracy rises from [3] to [1,2,3]. Mid-level cues (surface texture, the onset of a splash) are complementary across modalities before they are abstracted away. Fusion at stage 0 may be too low-level to help; report it either way, because an inverted-U curve is itself a finding. H5 Feedback (↺) beats the same stages without feedback, especially for the confusable weak and medium classes.

Modality dropout versus U-FFIA. HyperAVNet drops audio or video with probability p each (in U-FFIA's notation, pav = 1 − 2p and pa = pv = p). One per-sample mask applies at every fusion input and at the fused head, and the same switch simulates a missing modality at test time. U-FFIA Table V found a trade-off: no dropout (pav = 1) gives the best clean AV accuracy (0.917), while dropout is needed for single-modality use. HyperAVNet's auxiliary unimodal heads train each branch on its own regardless of dropout, so a small p (0.1) should be enough. Ablation D tests p ∈ {0, 0.1, 0.25}.

7  Pretrained models: teacher, extractor, distillation

All backbones share one interface: a list of stage tokens, shallow to deep. Any pretrained model can therefore be paired with the hypercomplex fusion stream. There are two modes. In distillation, a large pretrained AV teacher supervises the efficient student. In feature extraction, frozen (or partly unfrozen) pretrained backbones feed a hypercomplex side network, ladder-style, optionally from cached features.

7.1  Feature-extraction mode (cheapest training)

extract_features.py runs frozen backbones once over k augmented views of every training clip (one view for val and test) and stores the stage tokens in fp16. Training then only updates the hypercomplex fusion network and heads: about 1.24 M trainable parameters in configs/frozen_timm_side.yaml. This mode suits large sweeps (e.g. the full fusion-depth × algebra grid) and is a strong "frozen foundation features" baseline in its own right.

Reparameterisation. reparameterize_hypercomplex(model) folds every assembled Hamilton kernel into a plain nn.Linear or nn.Conv. Its outputs are identical (unit-tested). This removes the per-forward kernel assembly, which makes inference about 30% faster on CPU. Training saves this form as deploy.pt.

What to claim. Hypercomplex layers reduce stored and optimised parameters (model size, memory, communication), not arithmetic: the assembled kernel is dense, so FLOPs equal the real network's. Compute efficiency comes from the compact backbone design instead: 1.18 GMACs per clip, with the video branch at 82% of it. To reduce FLOPs further, shrink dims, num_frames or the input size. Do not attribute FLOP savings to the algebra.

10.2  Candidate contribution statements (keep only those the results support)

  1. A fully hypercomplex audio-visual architecture for FFIA, with Hamilton-product weight sharing in the backbones, attention, fusion and heads, at 3.7×–10× fewer parameters than the real-valued equivalent.
  2. Hypercomplex Component Fusion: modality views and their multiplicative interactions are encoded as the components of a quaternion or octonion and mixed by a single Hamilton product, with a constant parameter cost whatever the algebra.
  3. A systematic deep-to-early fusion study with zero-initialised cross-modal feedback, identifying where audio-visual fusion helps FFIA.
  4. Multi-level distillation from the strongest pretrained audio (PANNs CNN10) and video (S3D) models on AV-FFIA into a 2 M-parameter hypercomplex student, and a frozen-feature side-network variant.
  5. State-of-the-art accuracy on AV-FFIA (> 0.917, the published cross-attention result) with 16× fewer parameters and 52× fewer MACs, and better robustness to noise than U-FFIA (Table B). Only if Table 7 and the robustness runs confirm it.

10.4  Checklist before submission

  • Confirm the split with the authors: the code rule gives 21,400 train clips, the paper's text says 21,000.
  • Obtain U-FFIA's bubble and pump noise recordings (or comparable ones) for robustness.noise_dir; white-noise results are not comparable with their Table III.
  • Re-run the U-FFIA-like baseline through this pipeline, so the comparison does not depend on differences in preprocessing.
  • Use 3 seeds for every reported number; add significance tests for the closest comparisons.
  • Report parameters and compute in U-FFIA's unit (GMACs, which they call FLOPs), and state plainly that hypercomplex layers do not reduce compute.
  • Report the teacher's size and cost next to the student's, so readers see what distillation buys.
  • Count teacher pretraining data (AudioSet, Kinetics) as external data in the comparison.
  • Tune the frame count (U-FFIA hints at 20), the audio hop and the input size on val only, never on test.
  • Include confusion matrices: weak vs medium is the hard pair and the most informative analysis.
  • Release the configs and the manifest builder, so the split can be reproduced exactly.
